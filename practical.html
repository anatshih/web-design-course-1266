2. ماذا تجهّز للتسليم؟

أنشئ مجلداً واحداً يحتوي على المشروع كاملاً والتقرير، ثم اضغطه بصيغة ZIP.

ملفات التطبيق

  • index.html: الصفحة الرئيسية.
  • style.css: تنسيق الصفحات.
  • script.js: البرمجة والتفاعل.
  • أي صور أو خطوط أو ملفات إضافية يحتاجها التطبيق.

تقرير Word أو PDF

  • اسمك ورقمك الجامعي واسم المشروع.
  • فكرة المشروع وخطوات تنفيذه.
  • صور من واجهة التطبيق.
  • شرح الوظائف البرمجية، خاصة البحث والفلترة والحفظ.
  • التحديات التي واجهتك وكيف عالجتها.

اختبر نسخة المشروع بعد فك الضغط في مجلد جديد، وتأكد من أن الملفات والصور تعمل قبل رفع الملف.

3. كيف تسلّم المشروع؟

  1. اضغط المجلد كاملاً بصيغة ZIP. ضمّن ملفات التطبيق والتقرير وكل المرفقات اللازمة.
  2. ارفع الملف المضغوط إلى خدمة مشاركة ملفات. أنشئ رابط مشاركة يتيح للمشرف الوصول إلى الملف وتنزيله.
  3. تحقق من صلاحية الرابط. لا ترسل رابطاً يتعذر على المشرف فتحه أو تنزيل ملفه بسبب إعدادات المشاركة.
  4. افتح البوابة الأكاديمية وأرسل رسالة إلى مشرف المقرر. ضع رابط الملف في نص الرسالة، مع اسمك ورقمك الجامعي واسم المشروع.
  5. راجع الرسالة والرابط ثم أرسلها. احتفظ بنسخة من ملفك والرابط الذي أرسلته.
الموعد النهائي: آخر أسبوع قبل بدء الامتحانات النظرية.
ما المعلومات التي أكتبها في الرسالة؟

عنوان مقترح: تسليم مشروع تقنية تصميم صفحات الويب 1266 — الاسم والرقم الجامعي.

نص الرسالة: الاسم، الرقم الجامعي، اسم المشروع المختار، ثم رابط مشاركة ملف المشروع المضغوط.

طريقة التسليم المعتمدة هي إرسال رابط الملف برسالة عبر البوابة الأكاديمية إلى المشرف. لا تعتمد على تسليم الملفات شخصياً في المختبر.

4. مناقشة المشروع عبر Teams

ستكون هناك مناقشة للمشروع عبر Microsoft Teams، وسيُحدد موعدها لاحقاً.

استعد لتشغيل مشروعك وعرض وظائفه وشرح الكود الذي كتبته، خاصة إضافة البيانات وتعديلها وحذفها، والبحث والفلترة والحفظ، وفق متطلبات المشروع المختار.

قبل المناقشة: جهّز ملفات المشروع على جهازك، وجرّب تشغيله، وتأكد من استعدادك لمشاركة الشاشة وشرح عملك.

5. تحقّق قبل إرسال الرابط

استخدم القائمة لمراجعة تسليمك. وضع العلامات هنا للمساعدة في المراجعة ولا يُعد إرسالاً للمشروع.

أسئلة شائعة

هل أنفذ المشاريع الثلاثة؟

لا. اختر مشروعاً واحداً فقط من الخيارات الثلاثة ونفذ متطلباته.

هل يمكن العمل ضمن مجموعة؟

لا. العمل فردي.

هل أرسل ملفات المشروع مرفقة بالرسالة؟

اضغط الملفات والتقرير في ملف ZIP، وارفع الملف وأنشئ رابط مشاركة له، ثم أرسل الرابط برسالة عبر البوابة الأكاديمية إلى المشرف.

متى أسلّم المشروع؟

حتى آخر أسبوع قبل بدء الامتحانات النظرية.

هل يكفي تصميم صفحات دون تفاعل؟

لا. المطلوب تطبيق يعمل ويتفاعل مع المستخدم باستخدام JavaScript، وفق الوظائف المحددة في المشروع المختار.

هل أحتاج إلى PHP وقاعدة MySQL لهذه المشاريع؟

الخيارات الثلاثة هنا تعتمد على HTML وCSS وJavaScript وLocalStorage. دروس PHP وMySQL وتمارينها جزء من تعلم الوحدة الخامسة.

هل يكفي إرسال صور للتطبيق أو التقرير وحده؟

لا. يجب أن يحتوي الملف المضغوط على ملفات التطبيق القابلة للتشغيل مع التقرير والمرفقات اللازمة.

لماذا لا يستطيع المشرف فتح الرابط؟

راجع إعدادات مشاركة الملف، وتأكد من أن المشرف يملك صلاحية الوصول والتنزيل. اختبر الرابط قبل إرساله.

كيف ستتم المناقشة؟

عبر Microsoft Teams في موعد سيُحدد لاحقاً. جهّز التطبيق لتشغيله وعرضه، واستعد لشرح الكود ووظائفه.

إدارة المهام — متطلبات التنفيذ

الفكرة العامة

تطبيق ويب تفاعلي متكامل يهدف إلى إدارة المهام اليومية. يسمح للمستخدم بإضافة المهام وتعديلها وحذفها وتغيير حالتها مع واجهة جذابة وسهلة الاستخدام.

المتطلبات الأساسية

الوظائف الأساسية التي يجب أن يحتويها التطبيق:

إدارة المهام:
  • إضافة مهمة جديدة
  • تعديل مهمة موجودة
  • حذف مهمة
  • تغيير حالة المهمة (مكتملة أو غير مكتملة)
بيانات المهمة - يجب أن يحفظ النظام البيانات التالية:
  • العنوان: نص إجباري لا يجوز تركه فارغاً
  • مستوى الأولوية: قائمة منسدلة إجبارية (منخفضة / متوسطة / عالية)
  • التاريخ: حقل اختياري لتنظيم العمل
  • الحالة: مكتملة أو غير مكتملة
العرض والتخزين:
  • عرض جميع المهام بوضوح على الشاشة
  • تمييز المهام المكتملة (بخط مشطوب أو لون مختلف)
  • الحفظ التلقائي في LocalStorage
  • استرجاع المهام عند فتح الصفحة بدون إعادة تحميل

التقنيات المستخدمة

HTML5 CSS3 JavaScript LocalStorage DOM Manipulation Array Methods

المتطلبات المتوسطة

البحث: توفير شريط بحث للبحث عن مهمة من خلال كلمات من عنوانها
الفلترة: أزرار أو خيارات لتصفية عرض المهام:
  • حسب الحالة (مكتملة / غير مكتملة)
  • حسب مستوى الأولوية (عالية / متوسطة / منخفضة)
الترتيب: إمكانية ترتيب المهام المعروضة:
  • حسب التاريخ (الأحدث أو الأقدم)
  • حسب الأولوية (الأهم أولاً)

مميزات التميز - Bonus

يمكنك اختيار واحدة أو أكثر من المميزات التالية لإظهار مهاراتك المتقدمة:

إحصائيات: شريط تقدم يعرض نسبة المهام المكتملة (مثلاً: 3 من 5)
تحسينات بصرية:
  • رسوم متحركة عند الإضافة والحذف
  • تأثيرات بصرية احترافية
تفاعل متقدم: سحب وإفلات (Drag & Drop) لإعادة ترتيب المهام
تنبيهات وتنويهات:
  • رسائل تأكيد قبل الحذف
  • تنبيهات عند إضافة أو تعديل المهام

البنية البرمجية - كيفية كتابة الكود

لتنظيم الكود وتسهيل قراءته:

استخدام Array: استخدم "مصفوفة" (Array) لتخزين قائمة المهام بالكامل
استخدام Object: استخدم "كائن" (Object) لتمثيل بيانات كل مهمة على حدة
مثال توضيحي للبيانات: 

const task = {

  id: 1,

  title: "إنهاء المشروع",

  priority: "عالي",

  date: "2024-12-31",

  completed: false

};
نصيحة برمجية: قسم الكود إلى دوال (Functions) منفصلة لكل وظيفة، استخدم أسماء متغيرات واضحة وذات معنى، وأضف تعليقات توضح آلية عمل الكود

خطة العمل (المراحل التطبيقية)

اتبع هذه المراحل بهذا الترتيب لضمان إنجاز المشروع بسلاسة:

المرحلة المهام المطلوبة
1. التخطيط والتصميم رسم وتخيل شكل الواجهة، تحديد التطلبات والعناصر الأساسية، تصميم الواجهة
2. بناء الهيكل كتابة الكود باستخدام HTML، تنسيق العناصر وترتيبها باستخدام CSS
3. البرمجة الأساسية كتابة كود JavaScript لتفعيل وظائف الإضافة والحذف والتعديل والتغيير الحالة
4. الفلترة والبحث دمج وظائف البحث والفلترة والترتيب حسب الخصائص
5. الاختبار إجراء اختبار شامل للتطبيق على المتصفح والتأكد من عدم وجود أخطاء
6. التقرير والتسليم كتابة التقرير النهائي وتجهيز الملفات للتسليم

المتطلبات الأساسية

عمليات CRUD (الأساسية):
  • Create: إضافة ملاحظة جديدة

  • Delete: حذف ملاحظة

  • تاريخ الإنشاء: يتم إنشاؤه وحفظه تلقائياً بدون تدخل المستخدم
  • تاريخ التعديل: يتحدث تلقائياً عند تعديل الملاحظة
طريقة العرض والتخزين:
  • عرض الملاحظات في شكل بطاقات (Cards)

  • استرجاع الملاحظات عند فتح الصفحة

المتطلبات المتوسطة

البحث الفوري (Real-time Search):
  • يجب أن يحتوي التطبيق على شريط بحث
  • يبحث في "العنوان" و "المحتوى"
  • البحث يعمل فوراً أثناء كتابة المستخدم (حدث input)
  • ليس بعد الضغط على زر بحث
التصنيف والفلترة:
  • تصنيف الملاحظات عند إضافتها في الفئات (دراسة، عمل، شخصي)
  • أزرار أو خيارات لتصفية العرض
  • مثلاً: إظهار ملاحظات "الدراسة" فقط، أو إظهار "الجميع"
الترتيب: إمكانية ترتيب الملاحظات المعروضة:
  • حسب التاريخ (الأحدث/الأقدم)
  • حسب الاسم (أبجدياً)

مميزات التميز - Bonus

يمكنك اختيار واحدة أو أكثر من المميزات التالية:

للإدارة:
  • زر تثبيت الملاحظة (Pin) في أعلى القائمة
  • تمييزها بنجمة (مفضلة)
  • تغيير لون البطاقة
للإحصائيات:
  • عرض عدد الملاحظات الكلي
  • عدد الملاحظات لكل فئة
  • إحصاء لعدد الكلمات
للواجهة:
  • وضع ليلي/نهاري (Dark Mode)
  • تصميم متجاوب يعمل على الهواتف
  • رسوم متحركة عند الحذف والإضافة
  • تنبيهات احترافية

البنية البرمجية - كيفية كتابة الكود

هيكل البيانات:
  • نزخ الملاحظات في Array
  • كل ملاحظة هي Object منفصل
مثال توضيحي للبيانات: 

const note = {

  id: 1,

  title: "ةمهم ةظحلام",

  content: "...انه ةظحلاملا ىوتحم",

  category: "ةسارد",

  createdDate: "2024-12-15",

  lastModified: "2024-12-15 10:30"

};
نصيحة برمجية: قسم الكود إلى دوال صغيرة (Functions) - دالة لإضافة، دالة للبحث، دالة للعرض، إلخ. هذا يجعل الكود أسهل للقراءة والتعديل

خطة العمل (المراحل التطبيقية)

المرحلة المهام المطلوبة
1. التخطيط والتصميم تخيل شكل الصفحة (أين ثحب البحث؟ أين الملاحظات؟) وتحديد الألوان والتصميم
2. بناء الهيكل كتابة HTML وتصميم نموذج الإدخال وتنسيق باستخدام CSS
3. البرمجة الأساسية تفعيل وظائف الإضافة والعرض والحذف والتعديل (CRUD)
4. نيزختلا التأكد من حفظ البيانات في LocalStorage واسترجاعها عند فتح الصفحة
5. البحث والفلترة تفعيل شريط البحث الفوري وخيارات الفلترة والترتيب
6. الاختبار والتقرير اختبار شامل والتأكد من عدم وجود أخطاء وكتابة التقرير
